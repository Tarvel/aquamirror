1. Executive Summary
AquaMirror is a Digital Twin-powered smart water management platform purpose-built for Nigerian university campuses. It creates a real-time virtual replica of the campus water distribution network — including storage tanks, pumps, pipelines, valves, and distribution nodes — and uses that mirror to continuously monitor flow, detect leaks, predict pipe failures, and optimise water allocation.
Nigerian universities lose an estimated 25–40% of their treated water supply to leaks, unmetered usage, and distribution inefficiencies before it reaches end users. For a campus of 15,000–30,000 students, this translates to millions of naira in wasted water and maintenance costs every year. AquaMirror addresses this crisis head-on with a solution engineered specifically for the Nigerian context: intermittent grid power, aging galvanised and uPVC pipework, variable borehole pressure, and limited O&M budgets.
Core Value Proposition
AquaMirror reduces university water loss by up to 35%, cuts reactive maintenance spend by 50%, and pays back its full implementation cost within 18–24 months — while generating real-time water intelligence the university can act on today.
The system is built on four proven technology pillars:
Low-power IoT sensor nodes (pressure, flow, and acoustic leak-detection) deployed at critical network junctions
A ruggedised edge-computing gateway per zone that buffers data during NEPA outages and syncs to cloud on restoration
An open-source Digital Twin engine (EPANET-based hydraulic model) that runs what-if scenarios and flags anomalies in real time
A web and mobile dashboard with Yoruba, Hausa, and Igbo localisation options, accessible to facility managers with no engineering background
AquaMirror is not a foreign smart-city transplant — it is designed to survive Nigeria: solar-charged battery backup, GSM/4G primary communication with LoRaWAN fallback, local maintenance partnerships, and a hardware-as-a-service pricing model that eliminates large upfront capital requirements for cash-constrained universities.

4. System Architecture
4.1 Architecture Overview
AquaMirror is a five-layer architecture designed for resilience in low-infrastructure environments. Each layer is independently operable, ensuring graceful degradation when any single component fails — critical for Nigerian conditions.
Layer 1: Physical Sensing Infrastructure
Sensor nodes are the nerve endings of the system. Each node integrates:
Electromagnetic or ultrasonic flow meters (non-invasive clamp-on type for retrofit installations on existing pipes)
Pressure transducers (0–16 bar range, rated for fluctuating borehole/pump pressure)
Acoustic correlator microphones for passive leak detection on buried pipes (detects high-frequency acoustic signatures of leaks through pipe walls)
Temperature sensors (monitors for thermal anomalies that precede pipe stress fracture)
Node MCU: ESP32-S3 microcontroller with onboard 4MB flash for local buffering
Power: 10W solar panel + 3.7V 5,000mAh LiPo battery (72-hour autonomy without sun)
Nigeria-Specific Hardware Choice
All sensors are selected for availability in Lagos, Abuja, and Port Harcourt electronics markets (Alaba International, Computer Village). Where imported, components ship through established Nile University/UNILAG procurement channels. Total BOM per sensor node: ₦45,000–65,000.
Layer 2: Edge Gateway & Local Network
Each campus zone (typically 3–5 buildings or one hostel block) is served by one ruggedised edge gateway:
Hardware: Raspberry Pi 4 (4GB RAM) in IP65 weatherproof enclosure with heat management for Nigerian ambient temperatures (up to 42°C)
Local mesh: LoRaWAN 868MHz for sensor node communication (2km range, penetrates buildings, extremely low power)
Primary WAN: 4G LTE SIM (MTN/Airtel dual-SIM failover) for real-time data upload
Fallback WAN: Campus Wi-Fi bridge where available
Local storage: 64GB SD card buffers up to 7 days of data during extended outages
Edge analytics: Lightweight anomaly detection runs locally — the gateway raises alarms even without internet connectivity
Layer 3: Cloud Data Platform
AquaMirror uses a hybrid cloud architecture with Nigerian data sovereignty in mind:
Primary hosting: Microsoft Azure Nigeria North (Lagos) data centre — data stays in-country
Time-series database: InfluxDB for high-frequency sensor data ingestion (10-second resolution per node)
Relational store: PostgreSQL for network asset registry, maintenance logs, and user management
Message broker: MQTT over TLS for reliable, low-bandwidth sensor data transmission
API layer: REST + WebSocket APIs for dashboard and third-party integrations
Layer 4: Digital Twin Engine
The heart of AquaMirror is a hydraulic Digital Twin built on the EPANET 2.2 open-source engine — the global standard for water distribution modelling:
Network model: A calibrated hydraulic graph of the campus pipe network (nodes = junctions, tanks, pumps; edges = pipe segments with diameter, material, and roughness parameters)
Real-time state estimation: Sensor readings are fused with the hydraulic model every 60 seconds using a Kalman filter to produce a complete network state estimate — including unmeasured nodes
Anomaly detection: The Digital Twin predicts expected pressures and flows at every node; statistical deviations >2σ from predicted values trigger leak/burst alerts
Scenario simulation: Operators can run what-if simulations (e.g., "what happens to hostel pressure if pump 2 fails?") before making changes
Pipe failure prediction: Regression models trained on pressure cycling data, pipe age, and material predict failure probability per segment
Layer 5: Dashboard & User Interface
The AquaMirror dashboard is designed for three user personas: the non-technical Facilities Manager, the Engineering Officer, and University Management.
Web application: React.js progressive web app, works on 3G connections and is mobile-responsive
Mobile app: Lightweight Android APK (iOS PWA) for field technicians — shows nearest leak location, step-by-step isolation instructions, and photo-upload for maintenance logging
Role-based access: Management sees cost/sustainability KPIs; engineers see hydraulic maps and anomaly queues; administrators see audit logs
Alert channels: In-app notifications, WhatsApp Business API integration (familiar to Nigerian operators), and SMS fallback

5. Operational Framework
5.1 Real-Time Flow Monitoring
Flow meters at tank outlets, pump discharge points, and building entry points report flow rates every 10 seconds. The Digital Twin aggregates these readings into zone-level water balance calculations. If water entering a zone consistently exceeds water leaving it (accounting for expected storage), a leak is suspected and investigated.
Zone-level metering follows the District Metered Area (DMA) methodology recommended by the IWA (International Water Association), adapted for campus topology.
5.2 Leak Detection Algorithm
AquaMirror uses a three-layer leak detection approach to minimise false positives — a critical concern in low-trust operational environments:
Layer 1 — Acoustic Screening: Acoustic correlator nodes on buried pipes continuously listen for the characteristic high-frequency sound signature (200–1200 Hz) of water escaping under pressure. This catches active leaks on buried infrastructure.
Layer 2 — Hydraulic Mass Balance: The Digital Twin's water balance calculation flags zones where inflow and outflow diverge by >3% over a 30-minute rolling window. This is the primary method for above-ground and joint leaks.
Layer 3 — Pressure Transient Analysis: Sudden pressure drops (>0.5 bar in <5 seconds) are characteristic of pipe bursts. The system detects and triangulates these transients to within ±20 metres of the break point.
5.3 Pipe Failure Prediction
Pipe failure prediction uses a Random Forest classifier trained on the following feature inputs:
Pipe material (galvanised steel, uPVC, HDPE, ductile iron)
Pipe age and estimated installation year
Historical pressure cycling frequency (number of on/off pump cycles per day)
Historical repair records for the segment
Soil type and burial depth (for corrosion-rate estimation)
Proximity to high-traffic vehicle routes (vibration-induced fatigue)
The model outputs a monthly Failure Probability Index (0–100) per pipe segment. Segments scoring >70 are flagged for scheduled replacement in the next maintenance cycle. This converts reactive emergency spend into planned capital expenditure.
5.4 Demand Forecasting
Water demand on a university campus is highly predictable: it follows academic calendars, lecture timetables, and weekly patterns. AquaMirror's demand forecasting module:
Uses a Prophet time-series model (developed by Facebook/Meta, open source) trained on 6–12 months of historical flow data
Incorporates academic calendar inputs (exam periods, public holidays, ASUU strike actions — unfortunately a Nigerian operational reality) to adjust forecasts
Generates 24-hour and 72-hour rolling forecasts, driving proactive pump scheduling and tank pre-filling before peak demand periods
Learns and improves monthly as more data accumulates
5.5 Water Allocation Optimisation
The optimisation module uses a linear programming solver to balance water allocation across zones subject to:
Available storage in each overhead/ground-level tank
Pump capacity and energy cost by time-of-day (cheaper to run pumps during off-peak grid hours)
Minimum pressure requirements per zone (0.7 bar at the furthest tap)
Prioritisation rules (e.g., student hostel medical bays always maintain supply)
Recommendations are surfaced to the pump operator as a simple daily schedule: "Start Pump 2 at 05:30, stop at 07:15; Start Pump 1 at 18:00…" — no engineering degree required to act on them.

7. Chemical Engineering Relevance
AquaMirror is deeply grounded in Chemical Engineering principles across multiple sub-disciplines:
7.1 Fluid Mechanics & Hydraulics
The Digital Twin engine is built on the Hazen-Williams and Darcy-Weisbach equations that govern steady-state and transient flow in pipe networks. Every pipe segment in the model is characterised by its roughness coefficient, internal diameter, elevation change, and minor loss coefficients at fittings — the same parameters taught in ChE fluid mechanics courses.
Pressure transient analysis (water hammer detection) applies the Joukowsky equation to model the pressure wave velocity in pipes following sudden valve closures — a key mechanism of pipe failure in poorly-managed systems.
7.2 Process Control & Systems Engineering
The pump scheduling optimisation is a classic process control problem: maintaining tank levels within setpoint bounds (Lo/Hi alarms with PID-like feedback) while minimising energy input. The system implements a supervisory control layer analogous to a SCADA-DCS architecture in a process plant.
The Kalman filter used for state estimation is identical in concept to the observers used in advanced process control (APC) to estimate unmeasured process states from available measurements.
7.3 Mass & Energy Balances
Zone-level water balance (analogous to a material balance envelope around a process unit) is the primary leak detection method. The principle: if accumulation ≠ in − out, there is an unaccounted loss. This is identical to the reconciliation of process flow data in plant operations.
7.4 Transport Phenomena
Water quality degradation in distribution networks is governed by reaction-diffusion transport: residual chlorine decays as a first-order reaction during transit time in pipes. The Digital Twin's residence time calculations directly apply transport phenomena to predict water quality at the point of use — relevant where tanks sit unmixed for days.
7.5 Process Optimisation
The multi-objective linear programming optimisation (minimise energy cost, maximise pressure equity across zones, subject to demand constraints) is a textbook operations research/optimisation problem from the Chemical Engineering curriculum. It demonstrates that ChE optimisation tools extend far beyond reactors and distillation columns into infrastructure management.

A.3 Glossary
Term
Definition
Digital Twin
A real-time virtual replica of a physical system that mirrors its state and behaviour using sensor data and physics-based models.
NRW — Non-Revenue Water
Water produced and distributed that does not generate revenue, including physical losses (leaks) and commercial losses (meter errors, theft).
DMA — District Metered Area
A discrete zone of a water distribution network, metered at its boundaries, used to calculate water balance and detect leaks.
EPANET
A public-domain hydraulic simulation programme for pressurised pipe networks developed by the US Environmental Protection Agency.
LoRaWAN
Long Range Wide Area Network — a low-power, long-range IoT communication protocol ideal for sensor networks in campus environments.
Kalman Filter
A recursive estimation algorithm that fuses noisy sensor measurements with a predictive model to produce optimal state estimates.
HaaS
Hardware-as-a-Service — a procurement model where hardware is leased rather than purchased, eliminating upfront capital expenditure.
